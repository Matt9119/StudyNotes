Threat Hunting Methodology

Hunt hypotheses are classified 3 ways:

  • Intel Driven — given intel to focus on
  • Enemy TTP Driven — uses the MITRE ATT&CK Matrix
  • Anomalous Driven — uses NIST or best practices
Remember

If you don't have a hypothesis, you're not threat hunting.

Ultimate goals
  • Lower the average dwell time of adversaries
  • Impose cost on adversaries — make them change their TTPs
  • Detect malicious behavior quicker and more frequently

Downtime between hunts generates lessons learned: What could you do better? Alternate detection capabilities? Can this be signaturized? How often should it be performed?

Incident Response: PICERL
6 Steps
1 · Prepare
The most crucial step — defines how your org manages threats. Proactive defense: define the OE, planning, OSINT research, signature development, hardening, DiD.
Know your OE — physical location, logical layout, security safeguards, users. Understanding it leads to Key Terrain: locality/area whose seizure or retention affords a marked advantage (JP 2-01.3). "Key Terrain Cyber" = critical enablers for mission success.
2 · Identify
Determine if an event is an incident, then its scope. An event is any observable occurrence (e.g. user connects to a share). An incident is a violation/imminent threat of violation of security policy (e.g. botnet DDoS, phishing malware, data extortion).
Key questions: What happened (who/what/where/when/why/how)? What makes this an incident? What's the scope? Does it impact ops? Does it match known adversary TTPs?
3 · Containment
"Stop the bleeding" — limit and prevent further damage.
Short term: immediate quarantine, remove the infected system from the network — don't pull the power plug. Long term: affected device can sometimes stay in service while investigation continues.
Use OCO methodologies (MITRE ATT&CK) to anticipate/react. Forensically image the system; sandbox the malware for analysis.
4 · Eradicate
Remove the root cause — every source of malware removed, every affected system cleaned/hardened: re-image drives, patch, run vuln scans.
Forensic process: standardize ops, know your data resources, be proactive in data collection, use a standard/methodical process, constantly review procedures. Config/infrastructure changes here are DODIN Ops' responsibility — DCO typically investigates/identifies only.
5 · Recover
Restore affected systems to normal ops. Validate: confirm vital systems operational, verify no further compromise signs, optionally test defenses (Cyber Threat Emulation) if time/partner allows. Then restore operations.
6 · Lessons Learned
Document and discuss what was learned — what worked, what needs improvement. Produces: After Action Report, MISREP, case notes, deliverables to mission partners (fix recommendations, security improvements).

Obfuscation Techniques

What is obfuscation?
Concealing data/files/processes/actions on a system. Methods: encoding (ciphertext, packers), steganography, phishing, jargon, adding meaningless code.
Decoding it
Look for oddly-colored images, off audio, encoded text. Tools: strings (embedded text), Steghide (extract hidden data from images), CyberChef (decrypt/decode by format — BASE64↔ASCII, HEX↔Dec, media input support).

Risk Management (NIST SP 800-30)

Risk = a function of the likelihood of a threat event's occurrence and its potential adverse impact.

  • Threat-source — natural (hurricane), human (internal/external), environmental (power/HVAC)
  • Threat — potential for a source to exploit a vulnerability
  • Vulnerability — a flaw that can present a security breach
  • Likelihood — probability of threat + vulnerability combining
  • Management Controls — safeguards/countermeasures that reduce risk

At a high level: balance risk exposure against mitigation cost, then implement countermeasures.

DiD Approaches
  • Uniform Protection — treat all systems as equally important; most common approach
  • Protected Enclaves — subdivide/separate networks (VLANs, VPNs, host/internal firewalls)
  • Information Centric — prioritize protecting information over systems; layer protection around the data
  • Vector-Oriented — ID threat vectors, secure each: identify the asset → rank by value → brainstorm attack paths → place controls on each vector

Virtual Machines & Containers
What are VMs?
  • Software that emulates a hardware system; runs on a system or server
  • Each VM runs a unique OS — multiple VMs can run on one server (e.g. Windows + Linux + macOS VM on one box)
  • The hypervisor creates and runs VMs
Type 1Type 2
Installed directly on hardware (e.g. ESXi)Runs on top of an existing OS (e.g. VMWorkstation, VirtualBox)
VMs in DCO
  • Virtual Desktop Environments — users log into a VM; segmentation adds security; easy to shut down during an incident
  • Windows/Linux VMs used on AF Weapon Systems
  • Used in malware analysis — sandboxes are purpose-built VMs emulating real machines
What are Containers?
  • Standard unit of software packaging code + dependencies to run reliably across environments
  • Multiple containers can run on a single OS instance
  • Lighter/more portable than VMs — fast spin-up, less storage

When a container stops, everything inside it is lost and resources return to the system.

Containers in DCO

Used for several DCO programs (ELK, Arkime).

Kubernetes: automates deployment of multiple containers on AF Weapon Systems — open source, automated rollouts/rollbacks, self-healing (auto restarts/fixes failing containers).
Concerns: error handling, team continuity of knowledge, expanded attack surface, log storage (in/outside container), vulnerabilities (outdated images, misconfig, insecure APIs).

DNS Sinkhole / Blackhole

Redirects DNS responses to prevent clients from reaching malware/spyware/spam destinations — traffic is sent to a non-routable IP (e.g. 0.0.0.0) or controlled environment. Can be built with a forward lookup zone using the malicious site's name, or via a blackhole list of known-offending servers.

Firewalls
5 Firewall Security Designs
TypeNotes
1. Packet (L3)Simplest — filters on IP/port criteria. High performance, but no protection against spoofing, fragmentation, or app-layer attacks.
2. Stateful Inspection (L4)Tracks TCP session state — only passes packets valid for the connection's state; prevents IP spoofing since packets must belong to a valid session.
3. Application Layer (L7)Understands app protocols (HTTP headers, FTP sequences); terminates/originates separate connections on each side; can restrict specific commands (e.g. FTP GET-only).
4. HybridCombines all three — can balance fast packet-level throughput with app-level security.
5. Next-Generation (NGFW)Highest class — deep packet inspection, app awareness, integrated IPS, cloud threat intel. Best against APTs. USAF uses Palo Alto NGFWs.
pfSense
  • Free, open-source, multifunctional (router/firewall/proxy/DNS/DHCP/VPN)
  • Filters at L3/L4/L7 — has NGFW capabilities
  • Runs a customized FreeBSD; managed entirely via web GUI

Rule tips: make rules as close to the user as possible; explicit Deny-All should be your last rule.

Snort

What is Snort?
A NIDS (can also run as IPS). Built in 1998 as a sniffer on top of tcpdump. Rule/signature based, with preprocessor engines for fragmentation and initial packet analysis. Latest: Snort 3.9.2 (multi-threading, reworked TCP handling).
3 operational modes
Sniffer — decodes and dumps packets like tcpdump (snort -d -v -a -e).
Packet Logger — saves packets in flat ASCII/tcpdump/XML/DB formats (snort -b -l /var/log/snort).
NIDS — full analysis with plugins: portscan detection, IP defrag, TCP reassembly, app-layer analysis (snort -i eth0 -c /etc/snort/snort.lua). Default mode if no switches given.
snort.lua
Operational config file (was snort.conf in 2.x). Sets logging/alerting/rules/paths/variables. Default path: /usr/local/etc/snort/snort.lua. Variable suffixes identify type: _PATH, _NET, _PORT.
"include" keyword
Pulls in other rule files: include <file path/name>. Default path RULES_PATH = '/etc/snort/rules/'.
Placement
Internet interface, DMZ, server farms, inter-subnet connections. Must be inline for Reject/Drop/Sdrop (NIPS); can run off SPAN ports if only listening (NIDS).
Snort Rules

A rule picks out matching traffic and takes an action. Usually a single line. Two sections: Rule Header (action, protocol, source/dest ports+IPs) and Rule Options (what to inspect, alert message).

action protocol source direction destination ( options )
IP addresses: must be IP (no hostname lookup), CIDR notation, negation with !, variables with $ (e.g. EXTERNAL_NET !$HOME_NET).

Direction operators: -> (one-way) · <> (bidirectional). Range operator : — [n1]:[n2] range, :[n] ≤n, [n]: ≥n.
Rule Options

Options separated by ;; keyword/argument separated by :. 4 categories: General, Payload, Non-payload, Post-detection.

  • msg — message for the alert/log: msg: "External SMB connection attempt";
  • reference — links to external ID systems (e.g. CVE)
  • sid — unique rule ID (<100 reserved, 100–1,000,000 = Snort distro rules, >1,000,000 = local rules)
  • rev — revision number for tracking rule updates
alert tcp any any -> any 80 (content:"BOB"; sid:1000983; rev:1;)

Tip: use VIM to highlight incorrect rule syntax. View live alerts: tail -f /var/log/snort/alert.

TCPDump

Free (BSD-licensed), on most Linux/Unix systems. Command-line packet capture — basis for most network-based defense tools. Useful for proving your own tool didn't cause an MP network outage (run TCPDump on yourself).

Indicators of Compromise
What is an IOC?

An artifact observed on a network/OS that, with high confidence, indicates a computer intrusion. Often used after-the-fact — improves early detection, generates IDS/IPS rules, creates AV signatures.

Types of IOCs
  • Atomic — a single data fragment that alone indicates adversary activity (e.g. a known bad IP, domain, or executable)
  • Computed — developed from incident material (e.g. a file hash matching a known-malicious executable)
  • Behavioral — atomic + computed combined into a behavior profile (e.g. a malicious Word macro spawns cmd.exe and connects to a known-bad domain to pull files matching a known malware hash)
Common IOCs
  • Unusual outbound or internal network traffic
  • Changes in / suspicious behavior of privileged accounts
  • Excessive failed logins followed by a success
  • Mismatched port-application traffic
  • Suspicious registry or file system changes
  • Uncommon DNS requests
  • Processes running outside their expected location

Network Mapping

Identifying what computers/devices are on your network — to defend a network, you must first know what's on it. Conducted during Functional Mission Analysis-Cyber (FMAC).

Importance to DCO: maps are the basis for defensive strategy; needed to determine weak points/vulnerabilities (part of Environment Characterization).
Information Gathered

IP addresses · open ports · network services · hostnames · OS types · data flow · communication links

Methods of Network Mapping
  • Windows PowerShell — ping-sweep a subnet, use cmdlets to portscan a host/subnet
  • Linux — for-loops to ping-sweep or portscan
  • Nmap — free/open-source, CLI or GUI (Zenmap, which can also generate network maps)

Network Miner

GUI for sniffing live traffic (available in CVA/H). Primary purpose: parse captured pcaps — can aggregate multiple files, retrieve pcaps/live traffic from remote machines.

  • Host tab — IPs seen, fingerprinted OS icon, hostname, geolocation, open ports; color-code hosts to trace a user's actions
  • Files tab — reassembled/extracted files (from HTTP, SMB, FTP, TFTP, SSL, TLS)
  • Message tab — emails, IRC/IM chats, social media
  • Credentials tab — sniffed usernames/passwords
  • Parameters tab — name/value data extracted from traffic (e.g. HTTP query strings)
  • Keywords tab — search captured traffic (case-sensitive), shows frame + source/dest

SIEM vs. SOAR

Both collect data from sensors, firewalls, IDS/IPS, etc. SIEM aggregates/correlates data across systems to generate alerts. SOAR (Security Orchestration, Automation and Response) integrates 3rd-party threat feeds and acts as the remediation/response engine for those alerts.

Host Survey & Host-Based Security

A Host Survey gathers detailed information about what's happening on your devices — establishes an "Environment Characterization" snapshot, ideally before exploitation occurs. Anything questionable found must be validated as stay/go.

Importance to DCO: known baseline understanding, "pattern of life" research, avoids re-investigating already-validated items, enables proactive vuln discovery, basis for defensive measures.
Types of Info Gathered

Process list · users (admin & non-admin) · installed software · auto-running programs · network connections · shared folders · installed/running services

Local CollectionRemote Collection
Physically log into each host — time/effort scales badly with enclave sizeInteract with all hosts from a central location; scalable given appropriate accesses

Remote collection is favored operationally for its scalability.

Trusted Tools

Software tested/verified to safely interact with or retrieve info from a host. Never fully trust tools already on the network you're monitoring/hunting — use binaries from your own system instead.

Sysinternals Suite

Windows admin toolset (docs.microsoft.com/sysinternals) — run as Administrator.

  • Process Explorer — hierarchy of processes, open windows/files, per-process data, CPU tracking, find which process loaded a DLL (DLL injection hunting), kill process trees, suspend processes. Cannot run remotely.
  • Autoruns — exhaustive list of auto-start processes; disable by unchecking; verifies executable signatures; can diff against a previous saved list
  • Handle — see what programs have a file/directory open, and the object types involved
  • ListDLLs — reports DLLs loaded into a process (or which processes have a given DLL loaded); shows digital signatures
  • Strings — finds human-readable text in apps/DLLs (e.g. an unusual URL); usage: strings <file>
  • Streams — reveals Alternate Data Streams (ADS), which can be used to hide data in the Windows file system
Endpoint Security

Endpoints are physical devices that connect to and exchange info with a network — mobile devices, desktops, VMs, embedded devices, servers, and IoT (cameras, thermostats, smart speakers, etc).

EDR — Endpoint Detection & Response

Agents placed on end-user devices to monitor/protect them — varying capability levels: AV, host IDS/IPS, info gathering (memory, processes, network connections). The Air Force uses Windows Defender Enterprise.

Windows Defender Enterprise

Prevent/detect/investigate/respond to advanced threats. Three important capabilities: Vuilnerability Managemnet, Automated Investigation and Response (AIR), and Threat Analytics

Vulnerability Management
Continuously prioritizes the biggest risks on critical assets and provide security recommendations.
Continuous Asset Discovery and Monitoring: Measure risk compliance against established benchmarks, authenticated scanning of devices, hardware/firmware assessment).
Risk-based intelligent prioritization: Focuses on emerging threats, pinpoints active breaches, protects high-value assets.
Remediation and tracking: Block vulnerable apps, gain insight into config changes to reduce risk, perform real time monitoring of remediation status.
Automated Investigation & Response (AIR)
Alert Triggered: Incident created → automated investigation begins → related alerts tied together.
Verdict Generation: Malicious, suspicious, or no threats found.
Device group config: Full (auto-remediate) · Semi (needs approval) · No automated response.
Remediation actions: quarantine file, remove registry key, kill process, stop a service.
Threat Analytics
Helps teams stay ahead of active threat actors/campaigns, popular/new attack techniques, critical vulnerabilities, common attack surfaces, and prevalent malware.
