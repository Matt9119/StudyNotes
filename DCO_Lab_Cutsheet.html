Local Survey vs. Arkime vs. Kibana
🖥️ Local Survey
Use when you need current, up-to-date, host-specific information — processes, services, local users, registry state, etc. right now on that box.
⚠
If you're checking a specific user's info (e.g. their HKCU registry keys), you need to be signed in as that user — HKCU only reflects the currently logged-in user's hive.
🦈 Arkime
Use when you need network traffic analysis — searchable sessions, filtering by IP/port/protocol, and PCAP export/download of what was captured.
📊 Kibana
Use when the data you need is already indexed in Elasticsearch — visualizing logs, metrics, or SIEM data across hosts/time, rather than raw packet capture.

Common Arkime Filters
FilterWhat it does
ip.src == <ip>Filter for a specific source IP
ip.dst == <ip>Filter for a specific destination IP
port.src / port.dstFilter by a specific source or destination port
http.uri == <path>Look for files/executables downloaded over HTTP — e.g. http.uri == "*.exe" finds anything ending in .exe
!=, &&, ||Operators — not equal, AND, OR
ℹ
A couple more that come up often: dns.host == <domain> for DNS lookups of a specific domain, and protocols == tcp / protocols == udp to narrow by protocol.
⚠
Destination port determines the protocol used — when you're not sure what a session is, check port.dst against the common ports table below before assuming.
💡
Always check the time range picker in the top corner before you start filtering — a search that returns nothing is often just pointed at the wrong window, not a dead end.

Check the time filter first. The single most common reason a search comes back empty is that the time range doesn't cover the window you actually care about.

Snort Essentials
📁Key Files

📝Rule Syntax
Structureaction protocol src_ip src_port -> dest_ip dest_port (options)
alert tcp any any -> 192.168.0.1 80 (msg:"HTTP Traffic Detected"; sid:1000001; rev:1;)
Common rule actions
ActionWhat it does
alertGenerate an alert, then continue normal packet processing
logLog the packet, no alert generated
passIgnore the packet
dropBlock and log the packet (inline/IPS mode only)
💡
Use VIM to edit rule files — its syntax color-coding makes it much easier to spot a malformed rule before you try to load it.
ℹ
SID quick reference: under 100 is reserved, 100–1,000,000 ships with Snort itself, and anything above 1,000,000 is for your own local rules — keep custom rule sids above that line so they don't collide.
✅Sanity-check a rule before relying on it
snort -T -c <config>Test the configuration/rules for syntax errors without actually running Snortsnort -T -c /etc/snort/snort.lua
